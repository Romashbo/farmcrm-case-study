# Архитектура и модель доступа

[К кейсу](../README.md)

Клиент-серверная система: React SPA, REST API на Express, PostgreSQL. Сервер — модульный монолит, не микросервисы. Платёжный контур — ЮKassa.

| Слой | Ответственность |
| --- | --- |
| SPA / React Router | Навигация и рабочие экраны |
| TanStack Query | Получение данных и управление кэшем |
| Express | Маршруты, middleware, контроллеры |
| Предметные сервисы | Бизнес-правила, транзакции, платёжный цикл |
| PostgreSQL | Сущности, ограничения, индексы и блокировки |
| Миграции | Версионирование структуры данных |

## Концептуальная матрица доступа

| Операция | Гость | Пользователь | Администратор |
| --- | --- | --- | --- |
| Регистрация, вход, список тарифов | Да | Да | Да |
| Свой профиль и подписка | Нет | Да | Да |
| CRM | Нет | Свои данные при действующей подписке | Те же условия для CRM |
| Управление пользователями и тарифами платформы | Нет | Нет | Да |

Отдельная реализованная модель организации с членством и ролями работников в изученной схеме не подтверждена. Не следует выдавать потенциальные роли ветеринаров и сотрудников за готовую RBAC.

## Интеграция с оплатой

Запрос создаёт локальную запись платежа и внешний платёж. Уведомление провайдера инициирует проверку статуса. При подтверждении применяется транзакционная активация. Для отсутствующего уведомления предусмотрена синхронизация.
