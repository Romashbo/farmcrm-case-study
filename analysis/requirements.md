# Требования и бизнес-правила (AS-IS)

[К кейсу](../README.md)

Реконструированы по исходникам, идентификаторы введены для портфолио. Не являются утверждённым ТЗ.

| ID | Функциональное требование |
| --- | --- |
| FR-01 | Регистрация, вход, профиль, бесплатный план |
| FR-02 | CRUD ферм, перенос животных при удалении |
| FR-03 | Карточки животных, поиск, фильтры, родословная, пагинация |
| FR-04 | Индивидуальные, групповые и фермерские события |
| FR-05 | Медицинская история, закрытие болезни |
| FR-06 | Создание, перенос, отмена, завершение напоминаний |
| FR-07 | Учёт яиц и мяса |
| FR-08 | Учёт препаратов и движений |
| FR-09 | Дашборд, статистика, экспорт |
| FR-10 | Тарифы, checkout, история и синхронизация платежей |
| FR-11 | Управление пользователями и тарифами администратором |
| FR-12 | Дополнительная защита выбранных операций |

## Бизнес-правила

| ID | Правило |
| --- | --- |
| BR-01 | Для CRM требуется действующая подписка |
| BR-02 | Основная бирка уникальна в пределах аккаунта |
| BR-03 | Бирка и пол обязательны |
| BR-04 | Загон при создании животного относится к выбранной ферме |
| BR-05 | Действуют лимиты ферм и карточек |
| BR-06 | При удалении фермы с животными требуется другая собственная ферма |
| BR-07 | Завершение pending-напоминания создаёт событие |
| BR-08 | Для определённых типов создаётся медицинская запись |
| BR-09 | События уровня фермы ограничены поддерживаемыми типами |
| BR-10 | Расход препарата положителен и не превышает остаток |
| BR-11 | При создании продажи указывается покупатель, списания — причина |
| BR-12 | Повторное подтверждение платежа не должно повторно активировать подписку |
| BR-13 | Платформенное администрирование доступно администратору |
| BR-14 | При включённой защите требуется дополнительное подтверждение операции |

## Нефункциональные аспекты

AS-IS: индексы, пагинация, транзакции, хеширование паролей, аутентификация. Нагрузочные испытания и достигнутые SLO не подтверждены.
